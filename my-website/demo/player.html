How a player-server aggregator works

This demo shows the same player-manager pattern used by sites that aggregate multiple streaming servers — built here with legally licensed media (Blender Foundation open movies and sample videos from test-videos.co.uk) so it can be studied and shared freely. It demonstrates four concepts:

  • Multi-source configuration — servers are data, not code: each has a name, a URL builder, and a priority rank.
  • Adaptive streaming (HLS) — one master playlist lets the player switch between 360p / 720p / 1080p based on bandwidth.
  • Fallback chain — if the highest-priority source fails to start within a timeout, the manager automatically tries the next source, and shows a clear error state when all sources fail.
  • Telemetry — anonymous client-side logging of startup time, fallbacks, and source health (no personal data is collected).
